# 租号玩商户运营周度数据看板（Pages 部署版）

## 一、项目介绍

这是租号玩商户运营团队的**周度数据看板**，支持转租和分销两大业务线的数据可视化分析。

- **转租看板**：核心概览、分渠道明细、TOP20游戏排名、TOP游戏×TOP转租商交叉分析、异常预警、发货履约与退款、店铺变化分析
- **分销看板**：核心概览、分销商类型明细、TOP20游戏排名、TOP游戏×TOP分销商交叉分析、异常预警、退款撤单分析、分销商变化分析

**部署效果**：将本项目部署到 GitHub Pages 或 Gitee Pages 后，团队成员只需访问网址，即可查看最新周度数据，无需登录、无需下载文件，打开即看。

## 二、目录结构

```
租号玩周度数据看板_Pages版/
├── README.md                    # 部署和使用说明（本文件）
├── index.html                   # 看板入口页面
├── convert_xlsx_to_json.py      # xlsx 转 JSON 工具（加速大数据加载）
├── 转换数据.bat                  # 一键批量转换脚本（Windows）
├── css/
│   └── style.css                # 样式文件
├── js/
│   ├── echarts.min.js           # ECharts 图表库
│   ├── xlsx.full.min.js         # Excel 解析库
│   ├── storageCache.js          # IndexedDB 数据缓存模块
│   ├── xlsx-worker.js           # Excel 解析 Web Worker（后台线程）
│   ├── dataProcessor.js         # 数据处理模块
│   ├── charts.js                # 图表渲染模块
│   └── main.js                  # 主逻辑
└── data/                        # 数据文件（每周更新这里）
    ├── sublet_current.xlsx/.json   # 转租本周数据
    ├── sublet_previous.xlsx/.json  # 转租上周数据（用于环比）
    ├── dist_current.xlsx/.json     # 分销本周数据
    └── dist_previous.xlsx/.json    # 分销上周数据
```

**核心逻辑**：页面打开时，`main.js` 会自动通过 HTTP 请求加载 `data/` 目录下的数据文件并渲染看板。
- **优先加载 JSON 格式**（速度快 10 倍以上）
- 如果 JSON 文件不存在，自动回退到 xlsx 格式
- 已解析的数据会自动缓存到浏览器，二次加载瞬时完成

## 三、首次部署（GitHub Pages）

### 步骤1：注册/登录 GitHub 账号

访问 <https://github.com>，注册或登录你的 GitHub 账号。

### 步骤2：创建新仓库

1. 点击右上角 **+** → **New repository**
2. 仓库名称（Repository name）：建议填 `zuhaowan-dashboard`
3. 可见性（Visibility）：选择 **Public**（公开仓库才能免费使用 Pages）
4. 勾选 **Add a README file**（可选）
5. 点击 **Create repository**

### 步骤3：上传所有文件

1. 进入刚创建的仓库页面
2. 点击 **Add file** → **Upload files**
3. 将本目录下的 **所有文件和文件夹**（index.html、css/、js/、data/、README.md）拖拽到上传区域
   - 注意：需要连同文件夹结构一起上传，css、js、data 文件夹不能丢
4. 拉到页面底部，点击 **Commit changes**

### 步骤4：开启 GitHub Pages

1. 在仓库页面，点击顶部的 **Settings**（设置）
2. 左侧菜单找到 **Pages**
3. 在 **Build and deployment** → **Source** 中，选择：
   - **Deploy from a branch**
   - Branch 选 **main**（或 master），目录选 **/ (root)**
4. 点击 **Save**

### 步骤5：访问看板

- 等待1-2分钟，GitHub Pages 会自动构建部署
- 部署完成后，在 Pages 设置页面上方会显示访问地址，类似：
  `https://你的用户名.github.io/zuhaowan-dashboard/`
- 复制该地址，在浏览器打开即可看到看板

## 五、每周更新数据

每周从 BI 系统导出新数据后，按以下步骤更新：

### 1. 准备数据文件

从 BI 系统导出4份 Excel 数据，重命名为以下文件名（文件名必须完全一致）：

| 文件名 | 说明 |
|--------|------|
| `sublet_current.xlsx` | 转租业务本周数据 |
| `sublet_previous.xlsx` | 转租业务上周数据（用于环比） |
| `dist_current.xlsx` | 分销业务本周数据 |
| `dist_previous.xlsx` | 分销业务上周数据（用于环比） |

### 2. （推荐）转换为 JSON 格式加速加载

**为什么要转换？** Excel 文件在浏览器端解析非常慢（20MB 文件可能需要 30 秒以上），转换为 JSON 格式后加载速度可提升 **10-50 倍**，且文件经 gzip 压缩后传输体积更小。

**转换方法（Windows）**：

1. 确保电脑已安装 Python（需安装 `openpyxl` 库：`pip install openpyxl`）
2. 将4个 xlsx 文件放入 `data/` 目录
3. 双击运行 `转换数据.bat`
4. 等待转换完成，`data/` 目录下会生成对应的 `.json` 文件

**转换方法（命令行）**：

```bash
python convert_xlsx_to_json.py data/sublet_current.xlsx
python convert_xlsx_to_json.py data/sublet_previous.xlsx
python convert_xlsx_to_json.py data/dist_current.xlsx
python convert_xlsx_to_json.py data/dist_previous.xlsx
```

> **说明**：转换后 JSON 和 xlsx 文件都保留在 data 目录下，页面会**优先加载 JSON**，没有 JSON 时自动回退到 xlsx。首次部署建议两种格式都上传，确保兼容性。

### 3. 上传到仓库

**GitHub 操作方式**：

1. 打开仓库页面，进入 `data/` 目录
2. 点击 **Add file** → **Upload files**
3. 将4个新文件拖入上传区域（同名文件会自动覆盖）
4. 拉到底部，点击 **Commit changes**
5. 等待1-2分钟，GitHub Pages 会自动重新部署

**Gitee 操作方式**：

1. 打开仓库页面，进入 `data/` 目录
2. 点击 **+** → **上传文件**
3. 拖入4个新文件
4. 点击 **提交**
5. 进入 **服务** → **Gitee Pages**，点击 **更新** 按钮重新部署
6. 等待几十秒即可

### 3. 验证更新

- 刷新看板页面（建议按 **Ctrl + F5** 强制刷新，清除浏览器缓存）
- 查看「当前周期」是否更新为最新日期
- 确认核心指标数据已更新

团队成员无需任何技术操作：

1. **打开网址**：直接在浏览器中输入部署好的访问地址

## 七、备选方案：手动上传数据

如果因网络或部署问题，自动加载数据失败，可以使用看板内置的手动上传功能：

1. 打开看板页面

## 八、常见问题

### Q1：上传新数据后，页面没看到更新？

A：有两种可能：
1. **Pages 还在构建中**：GitHub Pages 每次更新后需要1-2分钟重新构建，Gitee Pages 需要手动点「更新」，请稍等片刻。
2. **浏览器缓存**：按 **Ctrl + F5**（Windows）或 **Cmd + Shift + R**（Mac）强制刷新页面。

### Q2：国内访问 GitHub Pages 很慢怎么办？

A：建议使用 **Gitee Pages**，国内访问速度快很多。部署方式见上文第四节。

### Q3：数据敏感，不想公开怎么办？

A：有以下几种方案：
- **Gitee 私有仓库 + Gitee Pages Pro**（付费，支持私有仓库部署 Pages）
- **部署在自己的服务器**：将文件上传到任意支持静态文件托管的服务器（Nginx、阿里云 OSS + CDN 等）
- **企业内网部署**：放在公司内网服务器上，仅内部可访问

> GitHub Pages 的公开仓库数据是完全公开的，任何人都能访问。如果数据包含敏感信息，请务必使用上述私有部署方案。

### Q4：手机上能看吗？

A：可以。手机浏览器直接打开网址即可查看，看板支持响应式布局，会自适应屏幕大小。

### Q5：数据文件很大（20MB+），加载很慢/上传失败怎么办？

A：分两方面解决：

**上传问题（GitHub 网页上传 25MB 限制）**：

GitHub 网页界面上传单文件不能超过 25MB，如果转租数据文件超过 25MB，会上传失败导致访问时 404。解决方案：

1. **强烈推荐：转成 JSON 后再上传**（`convert_xlsx_to_json.py`），JSON 文件通常比 xlsx 小 30%-60%，经 gzip 压缩后传输体积极小
2. 使用 **Git 命令行**上传（支持最大 100MB/文件）：
   ```bash
   git add data/sublet_previous.xlsx
   git commit -m "update data"
   git push
   ```
3. 使用 **GitHub Desktop** 桌面客户端上传（同样支持 100MB）

**加载速度问题**：

1. 使用 **JSON 格式**替换 xlsx，加载速度提升 10-50 倍
2. 页面内置优化（自动生效）：
   - **Web Worker 解析**：Excel 文件在后台线程解析，不卡页面
   - **IndexedDB 缓存**：解析过的数据自动缓存，下次打开瞬间加载（基于 ETag 自动失效）
   - **进度条提示**：大文件加载时显示实时进度

### Q5+：缓存有什么用？怎么清空？

A：每次加载数据后，系统会自动将处理后的数据缓存在浏览器的 IndexedDB 中。下次加载相同文件时，直接从缓存读取，速度极快（通常 < 1 秒）。

缓存采用 **ETag/Last-Modified** 自动失效机制：文件内容更新后，缓存会自动失效并重新加载，无需手动清理。

清空缓存方式：
- 点击右上角「数据源」按钮 → 找到「数据缓存」区域 → 点击「清空缓存」
- 或在浏览器设置中清除站点数据

缓存会自动管理（最多保留最近 20 条），一般不需要手动清空。

### Q5++：只有分销数据，转租数据 404，会影响使用吗？

A：**不影响**。程序会自动检测哪些文件存在，只加载可用的数据：
- 如果只有分销数据，页面会自动切换到「分销周跟进」看板
- 如果只有转租数据，显示转租看板
- 两者都有则同时显示，默认展示转租

缺失的数据看板会显示「暂无数据，请上传数据文件」，不会报错也不会卡死。

### Q6：为什么打开页面是空白的/显示未加载数据？

A：可能原因：
1. **本地直接双击 HTML 文件打开**：由于浏览器安全限制，本地文件无法通过 `fetch` 读取同目录下的 Excel 文件。必须通过 HTTP 服务器（Pages 部署或本地启动 http server）访问。
2. **data 目录文件缺失或命名错误**：检查 `data/` 目录下4个文件是否齐全，文件名是否正确。
3. **Excel 文件格式不对**：确保导出的文件格式与模板一致，包含必要的数据列。

### Q7：能同时支持多周数据对比吗？

A：当前版本支持本周与上周的环比对比。如需更长期的数据对比，可以考虑扩展数据目录结构，此版本暂不支持。

## 九、技术说明（可选）

- 前端纯静态实现，基于 ECharts + SheetJS (xlsx)
- 数据文件为 Excel 格式，浏览器端直接解析
- 自动加载逻辑：页面初始化时通过 `fetch('data/文件名')` 请求数据文件
- 支持手动上传作为备选方案
- 无需后端服务，任何静态文件托管服务均可部署
